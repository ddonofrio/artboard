# Local drawing service

This adapter owns local configuration and the Node HTTP transport. It depends on workflows, agents, core and the Node image adapter. It does not import UI or Vite. `createDrawingService` serves `/api/runs` and `/api/models` through development and production entry points.

Startup exclusively creates `agents.local.json` from `agents.example.json` when missing. Existing files are never overwritten. Empty settings use localhost and model discovery. `AGENT_*` variables override connection settings; `ARTBOARD_CONFIG_FILE` selects an alternate local file. Configuration is loaded for each request and never returned to the browser.

`GET /api/models` calls the configured OpenAI-compatible `/models` endpoint (root URLs normalize to `/v1/models`) with any private API key on the Node side. It returns advertised IDs and a preferred selection, never connection settings, instructions or credentials. `POST /api/runs` accepts an optional `model` ID of 1–256 characters. That ID overrides every artist/reviewer model only in the freshly loaded request configuration while retaining role instructions. Requests without an override use the configured role/default models. Local configuration files are never rewritten by model selection.

POST requests follow `src/contracts/service.ts`. The response streams newline-delimited JSON containing stages, agent states, tools, lossless PNG previews, reviews and the final status. States describe context preparation, waiting for the model, processing tool arguments, executing a named tool and idle delivery. Invalid inputs, including batch UUIDs/indices, fail before model requests. Cross-origin requests are rejected. Disconnecting cancels model execution. Each stage uses an isolated scene host and the previous stage's validated scene. At most 50 scene references remain in memory for editing. Restarting the service expires those references.

Requests optionally override reasoning_effort (none, low, medium, high) and vision_image_divisor (integer 1-64, default 4). Both are isolated to the execution and apply to every role. SSE reasoning and partial function arguments are forwarded immediately with stable activity IDs so the UI can update a single entry while generation continues. Partial arguments are not executed as tools or included in execution counters. Only final reasoning snapshots are journaled; actual tools retain their full validated arguments. Workflow totals include independent review; workflow 1 delivers unreviewed with no reviewer inference. Model JPGs reduce both dimensions by the divisor; PNG previews and persisted JPGs remain full size.

Successful edit batches are replayed in an isolated presentation store to emit a separate preview for each operation, preserving atomic model edits and undo history. Previews carry a queue group shared by all figures/calls in a model response; later responses use a new group. Ellipses carry normalized center/radius geometry for radial fill animation. Intermediate presentation snapshots are saved under `outputs/workflow/<run UUID>/paint-r<revision>-<operation>.json` and `.jpg`. Final previews preserve the pending animation queues.

Browser and CLI execution share `runPersistence` and the Node `OutputStore`. Single deliveries go to `outputs/YYYYMMDD/<prompt>.jpg`; batches use the supplied batch UUID and one-based index under `outputs/batch/<UUID>/001.jpg`. Final events return the relative `output_path`. Every revision and stage draft is preserved as JSON/JPEG under `outputs/workflow/<run UUID>`, with handoffs and reviews in `workflow.json`. `outputs/logs/agent.jsonl` journals execution, including model prompts/responses, tool calls, reviews and terminal errors/cancellation, with inline image bytes and credentials removed. Pending writes are flushed even after failure or disconnect so generated partial scenes remain available. Persistence failures appear in the error stream and cannot be reported as a successful delivery.
