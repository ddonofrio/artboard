# Browser interface

The browser interface uses Vite, vanilla TypeScript, and CSS. It contains prompt, canvas, and monitor columns in the same proportions as Adventure. Prompt and monitor fit their content; the canvas frame fits its image. The background is `#171b22`. Frames use VGA box-drawing characters and the locally bundled IBM VGA 8x16 font at its native 16-pixel size. Outer frames use double lines; inner boxes and buttons use single lines. Frame titles have white brackets and yellow text. Top edges split around their titles instead of drawing behind them.

All interface text is in English. Prompt contains a text area, a borderless Send control on its bottom-right edge, checkboxes for batch input and editing the current scene, and a numeric workflow count from 1 to 7. Send is gray and disabled for empty input, undefined workflows or an active run, and white when ready. Cancel is available during execution. Inputs are disabled while a run is active. Canvas contains the 640 by 480 drawing surface, scaled to the column width at a 4:3 aspect ratio, and displays current previews. Monitor contains Stats and Real time log. Stats shows numerical tool-call, success, failure, retry, and average drawing run-time values, initialized to zero and reset for each Send operation.

The Model combo sits immediately below the prompt box. On page load, `GET /api/models` lists the IDs advertised by the configured OpenAI-compatible server, including non-chat IDs. Changes to the selection are saved in `localStorage` under `artboard.selected-model` and restored on reload when that ID is still advertised. Otherwise the server's preferred model is selected. Refresh reloads the list and preserves the current selection when still available. Unavailable browser storage does not block model selection or execution. Loading or failed discovery disables Send; failures appear in the activity log and Refresh allows retry. Send captures the selected ID for all creation agents and the reviewer in that execution, including all lines of a batch. The selection remains available for the next Send and can be changed between turns. It overrides model defaults only for that request, preserving private instructions and leaving local configuration untouched.

Reasoning level sits directly below Model with Default, Off, Low, Medium and High choices. Off sends reasoning_effort=none; Default omits the request override. The selection persists under artboard.reasoning-effort and is captured for every agent and batch line in a turn. Supported levels depend on the model/server; rejection remains visible without silently changing the selection. Image size has an editable divisor displayed as 1 / 4 by default (integers 1-64). It reduces both dimensions of model JPGs, including requested looks and reviewer drafts, without resizing the canvas or outputs. Send captures the divisor per turn and is disabled for invalid values.

The layer-count control has a live algorithm description directly below it, linked through `aria-describedby`. The shared catalog defines creation stages and the final-agent review loop for workflows 1 through 7: one artist without review, one artist with review, then two through six artists with review. The counter includes the reviewer and matches the selected workflow number. The text updates on input and after range normalization.

Real time log contains exactly three values, without section headings, all in the same inherited text color. The first shows each tool name and JSON parameters, model-provided thinking, or execution errors, limited to two visual lines. A FIFO queue keeps every entry visible for at least one second; bursts and later runs wait behind earlier entries. The last entry remains when the queue empties. The second describes the current creation stage or validation/correction pass immediately, independently of that queue. The third shows agent state immediately: idle, processing prompt, thinking, writing tool args, or executing tool (with the tool name). It returns to idle after delivery, failure or cancellation. State distinguishes processing prompt (including server prefill), receiving actual thinking, and writing streamed tool arguments. The thinking state displays its reported token count, or an estimate prefixed with ~ when usage is unavailable. The first log has no token counter; thinking scrolls to its two latest visual lines while tools/errors retain their first two lines. Deltas update the same current or queued activity, preserving its one-second slot and avoiding one slot per token. Model thinking is supplied only when the upstream response includes reasoning fields or inline think tags; it is not fabricated.

Each framed element establishes its own positioning context so nested borders stay inside their own boxes. ResizeObserver updates the glyph edges when a box changes size. The interface has no menus, tabs, keyboard shortcuts, API settings, file controls, or prompt inspectors.

Canvas changes use classical scanline spans over changed pixels, including solid fills, recolors and other drawing changes. The fill frontier advances vertically at 96 CSS pixels per second (approximately one CSS inch per second), accounting for the displayed canvas scale. Circles and ellipses fill through clockwise rays traced from their center toward the edge, with duration based on their displayed diameter. Browser previews are lossless PNG so compression noise does not repaint unrelated surfaces; model vision still uses JPEG.

Each model response owns a queue: its figures paint one at a time, including separate operations within an atomic edit batch and separate calls within that response. A later response starts its own queue in parallel without finishing earlier fills. Per-pixel ordering prevents an older animation from covering a newer painted pixel. Tool calls, stages, review, delivery, errors and cancellation do not fast-forward painting. Already received figures keep animating after the model finishes or is cancelled; leaving the page releases the animation scheduler. Repeated identical inspection/final previews do not restart or skip queued figures. Animation never blocks reading the event stream. When all queues finish the pixels match the rendered scene exactly, and persistence uses completed data independently of display timing.

`service.ts` lists server models, sends drawing requests and consumes newline-delimited events according to `src/contracts/service.ts`. Typing and changing drawing controls remain local; Send executes the chosen workflow through `/api/runs`. Batch input runs nonempty lines sequentially and stops after an incomplete result or error. Edit uses the last delivered scene reference; it requires a current drawing and expires when the local service restarts. Cancellation aborts the browser request and propagates to model execution. UI modules import only other UI modules and pure contracts; ESLint enforces this boundary. Model defaults, private prompts, endpoints and credentials are configured on the Node side in `agents.local.json`; only advertised model IDs and the preferred selection are returned to the browser.

Each batch Send allocates one UUID and supplies a one-based line index, including a single-line batch. The server automatically saves numbered JPGs under `outputs/batch/<UUID>` or dated prompt-named JPGs for ordinary drawings. Revision snapshots and journals are saved by the server regardless of animation timing. The canvas exposes the last delivered relative path through `data-output-path`.
